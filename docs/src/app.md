# The desktop app

`falcon-app` is falcon's version of Eagle's main window, built with egui. Its look comes from Eagle itself:

- **Colours:** dark is sampled from Eagle's window and its dark-theme stylesheet (`style/base/_color.scss`). For example, the content area is `#17191d`, the panels `#1f2023` and the accent `#3297ff`. Light, lightgray, gray, blue and purple are worked out from the stylesheets, and Auto follows the macOS appearance (see Themes below).
- **Fonts and icons:** SF Pro for text, plus Phosphor Light icons, which are MIT-licensed and close to Eagle's line icons.
- **Measurements:** taken from Eagle at 1280 × 800: 240 pt panels, a 48 pt toolbar, 27 pt sidebar rows and 139 pt cards.

## Sandbox

While falcon is in development, the app and the `falcon` CLI only open libraries inside `~/Falcon Sandbox`. Set `FALCON_SANDBOX` to use another folder. Opening, creating or switching to a library anywhere else (including over the HTTP API's `library/switch`) fails with a message saying so, and the Open and Create dialogs start in the sandbox. To work on a real library, copy it into the sandbox first.

The app opens libraries with `Library::open_or_restore` (see [Backups](library-format.md#backups)): when a library's `metadata.json` can't be read or parsed, the newest usable backup in its `backup/` folder replaces it before the library loads, and a message names the backup used and says the damaged file was kept in `backup/`. This covers the switcher, Open Library, libraries reopened on launch, dropped libraries and the library the app reopens after an API `library/switch`. The HTTP API's own `library/switch` still uses `Library::open`, so a damaged library fails there. Both refuse a library made by a newer Eagle than 4.0.0 (see [Newer libraries and outside changes](library-format.md#newer-libraries-and-outside-changes)); the app shows an alert saying which Eagle version saved it.

Libraries chosen in the switcher or with Open Library… are read on a background thread (see Several libraries below). Libraries reopened on launch, dropped on the window, opened from Try Again or Select Another Path… and the one reopened after an API switch are read on the main thread.

The library switcher (the library name at the top of the sidebar, or ⌘L) lists the open libraries, then the recent ones that are not open. Each row shows the library's `icon.png` at its left, or a folder glyph when there is none; the sidebar's library row shows the same icon. Right-clicking a row, or the ⋯ button on it, opens a menu with Change Icon… (pick a jpg, jpeg, png, webp or gif; it is scaled to 64 px on its shorter side and saved as the library's `icon.png`), Remove Icon (only when there is one; asks Remove or Cancel), and Show in Finder, and Remove from List, which takes the library out of the recent history (an open library stays open). Under the Recent section, Clear History… asks for confirmation in a Clear Library History dialog (Clear All or Cancel) and then keeps only the libraries that are open. Recent libraries are kept across launches even when their folder has gone: such a row is dimmed with a warning glyph and a tooltip saying the folder can't be found, and its menu offers only Remove from List (Show in Finder is disabled). Clicking it tries to open it like any other library, which brings up the missing-library screen described under Several libraries.

**Add to Other Library**, in the item menu (one item or the selection), the menu of a folder (sidebar or folder card), of a smart folder and of a tag group heading, lists the recent libraries other than the shown one, then Choose Library… for any other. Several items ask first. The copy runs behind the progress modal with Cancel, and a notice says how many items were added and how many the other library already had. The rules are in [Adding to another library](library-format.md#adding-to-another-library). The other library must be inside the sandbox; when it is also open in falcon, the items appear in its window at once.

**Convert WebP**, in the item menu when the item is a WebP, converts every still WebP in the selection to PNG or JPG (quality 100), after a warning that the files will grow, as Eagle's does. It runs behind the progress modal with Cancel. The item keeps its name, tags and everything else and takes the new extension and size; its thumbnail stays, except that an image no larger than 960 px on both sides shows its original instead, as in Eagle. Animated WebPs are skipped. falcon writes the new file under a temporary name and swaps it in only when complete, moves the old WebP to the Trash instead of deleting it (the way to get it back, since the step can't be undone with ⌘Z), and lays transparency on white for JPG (`falcon_library::webp_convert`).

**Clear Invalid Content…**, in the library switcher (Eagle hides it behind a modifier-click on its library button), scans the shown library's item folders on a background thread. An item whose original file is missing or whose folder holds nothing but its `metadata.json` is moved to the Trash; a folder in `images/` that belongs to no item and has no `metadata.json` is moved to the macOS Trash (Eagle deletes it); an item whose folder has gone is dropped. Nothing found says how many folders were looked at. Otherwise falcon says what it found and warns that a cloud sync must have finished, then cleans up on Clean Up and reloads the library, as Eagle does. Folders with a damaged `metadata.json` are left alone (`falcon_library::repair`).

Falcon refuses to create, open or add to a library inside the folder it is installed in (its `.app` bundle, or the folder holding a bare executable), as Eagle refuses ones in its install folder: removing or updating the app would delete them.

Below the library rows the switcher lists Open Library…, New Library…, Merge Another Library…, Empty Cache and Reload…, Show in Finder, Import Files…, Import Folders…, Import Eagle Package… and Import Inboard Backup…, then the collect window and Preferences. The new entries are described under Several libraries.

## Empty views

An empty grid says why, with an icon, a title and a line of text (`crates/falcon-app/src/ui/grid/empty.rs`, where the wording and rules are tested). While a search or any filter is active it reads "No Matches". Otherwise All, Recently Used and Random say "Drop Files Here" with an Import Folders… button, and so does a folder with no subfolders (a folder with subfolders shows only its subfolder cards, and a locked one its lock screen). A smart folder with no matches says so. Uncategorized and Untagged explain what gathers there, or say "All Sorted" and "All Tagged" when the library has items and none are left. The Trash says it is empty. The All Tags page says "No Tags Yet" when the library has no tags, and "No Matches" when its filter finds none.

## Viewer layout

Every viewer (image, GIF, RAW, SVG, video, audio, font, text, PDF, the cannot-preview page and the iCloud wait screen) opens in the middle of the window, in place of the toolbar, filter bar and grid, with the sidebar and the inspector still beside it, as Eagle's detail mode does. The inspector shows the viewed item: the selection follows it as you step through, so closing the viewer leaves the grid on that item. The viewer draws only inside its own rect, and its scroll, pinch, clicks and menus act only there. The span is `logic::viewer_span`; the bar is `media_view::bar_shell`, shared by every viewer.

## PDF viewer

Opening a PDF shows it in a reader instead of the image viewer: the pages in one continuous vertical column, with zoom, page navigation, find, text selection and a thumbnail/outline sidebar. Pages are drawn by macOS's PDFKit through the `falcon-pdf` crate (`crates/falcon-pdf`), which keeps every Objective-C call in one module and hands the app RGBA pictures. The reader is in `crates/falcon-app/src/ui/viewer/pdf.rs`.

The file is opened, rendered, searched and selected only on a worker thread, never on the UI thread, so a PDF whose contents are still in iCloud (or a 1,000-page book) can't freeze the window. While it opens the viewer says "Opening…", or "Downloading from iCloud…" when the file is dataless (its `SF_DATALESS` flag is set, read without starting a download; `pdf_view::icloud_only` is the one place to switch to a shared iCloud helper). A file PDFKit can't read shows a line saying why; a password-protected one asks for its password (see below). Off macOS the image viewer shows the preview instead.

Rendering: the UI asks the worker for the pages in view and one on either side, at the screen's pixel density rounded up to steps of about 4%, so pages are never blurry at rest. Each page picture is capped at 16 MP (pdf.js's own canvas cap), so past roughly 400% on a Retina screen a page is shown enlarged rather than re-rendered sharper. Pictures live as textures in an LRU cache of 128 MP for pages and 16 MP for thumbnails. While the zoom is moving, pages keep their old picture scaled; 160 ms after it stops they are rendered again at the new scale.

## 3D model viewer

Opening an obj, stl, ply, glb, gltf, 3mf or fbx item shows the model in an interactive viewer in the central panel, like the other viewers, with the shared bar (panels, back, counter, open, previous and next; Esc and ← → work as usual). The readers and geometry are `crates/falcon-library/src/model3d/` (one file per format, `geom.rs` for normals, edges, details and lighting, `math.rs` for vectors and matrices). The camera maths are `crates/falcon-app/src/logic/viewer3d.rs`, the viewer's state and vertex data `crates/falcon-app/src/model3d/`, the wgpu drawing `model3d/gpu.rs` and the viewer itself `ui/viewer/model.rs`. 3ds, dae and ifc are not read, so those items keep their QuickLook still, as does any model that fails to read. Without the wgpu renderer every 3D item shows its still.

### FBX

FBX files, binary and ASCII, are read by `model3d/fbx.rs` with the ufbx C library (MIT, https://github.com/ufbx/ufbx) through the `ufbx` crate, which compiles the vendored C source with `cc`.

- Every node with a mesh is drawn, with its world transform applied. Each material the node uses becomes one mesh in the tree, named after the node.
- Polygons are split into triangles with ufbx's triangulation, which handles concave faces. Normals come from the file, or ufbx generates them when the file has none.
- Each material gives its diffuse colour (times the diffuse factor) and opacity. Textures and UVs are not read, because falcon's model has no texture path, so a textured material shows its colour only.
- The scene is converted to the viewer's convention: right-handed, Y up. Sizes are in centimetres, the FBX default unit. The file's `UnitScaleFactor` is applied, so a model saved in metres still reads in centimetres, and a Z-up file stands upright.
- Skinned meshes are shown in their bind pose. Blend shapes, animation, cameras, lights, NURBS, vertex colours and external files are skipped.
- A broken file is an error, never a crash. ufbx's memory is capped (1 GiB while parsing, 2 GiB for the scene), node nesting is limited to 256 levels and output to 50 million vertices. The file is always parsed as FBX, so an OBJ renamed to .fbx is refused. An FBX without triangles is an error, like the other formats.
- The thumbnail at import, the Details panel, the mesh tree, measuring, snapshots and export work as for the other formats.
- The tests build a small box FBX in both encodings in code (ufbx can't write files) and check the triangles, material, transform, generated normals, unit scale, Z-up conversion, empty scenes and truncated or corrupt files.

## Duplicates

The sidebar's Duplicates entry (after All Tags) opens a page that works like Eagle's duplicate panel. Pick a method, **Identical Files** (byte-identical originals) or **Similar Pictures** (perceptual hash), and what to scan: All Items, the view the page was opened from (its items in grid order), or the items that were selected there (two or more). Scan runs on a background thread with a progress bar. Changing the method or the range clears the results.

Each group is a row of thumbnails under a checkbox ("N identical files" or "N similar pictures, the best copy picked"), and every group starts ticked. Each thumbnail shows its name, type, size, dimensions and, for similar pictures, its distance in bits from the first. The copy a merge keeps is outlined and marked "Kept". For similar pictures falcon puts the best copy first and keeps it, as Eagle does: the most pixels, then for the same format the bigger file, else the better format (PNG, BMP, JPG, JPEG, WebP, AVIF, JXL, HEIC, HEIF, JFIF; `merge::best_first`). Clicking a similar picture keeps it instead, and for any group the thumbnail menu has Keep This Copy, Open, Open in Default App and Remove from Group. Remove from List drops a whole group. A group left with one item leaves the list. Double-clicking opens the viewer. The similarity slider sets how many of the 64 bits may differ (10 by default, right is stricter) and scans again. A line gives the number of picked files and the space a merge saves.

**Merge Groups…** opens a review of the ticked groups. For the chosen group it shows the kept item, then radio buttons for its File Name, Link and Note, picked from the group's distinct values (the first by default), with Join all notes when there are several notes (joined by line breaks and cut to 4,096 characters, as in Eagle), and toggles for the group's folders and tags, all on by default. Merge asks once more, then applies `Library::merge_duplicates` (`crates/falcon-library/src/merge.rs`). The kept item takes the chosen values and the group's highest rating, and the others move to the Trash with their files untouched. A copy kept by one group is never trashed by another. The whole merge is one ⌘Z step: undo puts back the kept item's name (its file renamed back), link, note, folders, tags and rating, and brings the others out of the Trash. A summary then gives the files moved to the Trash and the space saved, with Keep Merging (the merged groups have left the list) and Done (back to the start). The code is in `crates/falcon-app/src/ui/grid/duplicates.rs`, with the group rules in `logic/`.

The scan fills the hash cache item by item so it can report progress (content hashes only for files that share their size with another), then calls the library's `find_exact_duplicates_in` or `find_near_duplicates_in` (see [Import](import.md)) on a copy of the library taken when the scan starts. Items outside the range never link two similar groups together. The cache is kept in memory for the session, keyed by item id and checked against the original's size and mtime, so a second scan only hashes new or changed files. Nothing is written to the library until a merge.

## Duplicate check on import

Every import from the app (drops, ⌘V, files passed to the app, the collect window) checks whether each file is already in the library, while the preference is on. The import thread stages the file without the library lock, takes the lock only to list items of the same size and extension, and compares the bytes with the lock released (`import_check`, see [Import](import.md)). A match is not committed: the staged copy is held in a queue and the thread goes on with the next file. When the batch has finished, the window takes the queue into a dialog; the thread never waits for the window. The code is in `crates/falcon-app/src/import_dupes.rs` (thread side and decisions, with tests) and `ui/dialogs/duplicates.rs` (the dialog).

The dialog, "Already in the library (N)", shows the existing item's thumbnail, name and first folder, the new file's size and target folder, two choices, Use the existing item (the default) and Keep both, a "Do the same for all N files" box when more than one file is held, and Import and Don't Import buttons. Return imports with the chosen option and Esc skips; with ⌘ held either answers for every file. A click outside doesn't answer. Use the existing item puts the existing item in the import's folders with their auto-tags and moves its date added to now (`Library::use_existing_for_import`); if that item has been deleted or trashed meanwhile, the file is imported instead. Keep both commits the held copy as a new item. Don't Import drops it, removing the staged copy. Each answer is one undo step and shows a notice ("Used the existing items for 2 files"). Held files count as done in the progress bar's "Added N". Held files still waiting when their library is closed are dropped.

### About

Falcon ▸ About Falcon opens a small window centred over the app: the app icon, the name, "Desktop asset manager for Eagle libraries", the version (from the crate version) and a line saying the code is licensed under MIT or Apache-2.0. OK, Esc or a click outside closes it. While it is open the menu commands wait, as they do behind Preferences. On the first menu build falcon removes winit's stock About item and inserts its own at the top of the application menu (`menu::ABOUT`); it is always enabled.

### Error logs

Falcon writes errors, such as a library that fails to open or a crash, to `~/Library/Logs/Falcon/falcon.log`, one line each with the local time and `ERROR`. When the file passes 1 MiB it is renamed `falcon.1.log` (replacing an older one) and a new log starts. Help ▸ Error Logs opens the file with the default app, creating it first if it is missing. The log is for diagnosis only; nothing is sent anywhere.

### Debug report

Help ▸ Export Debug Report… asks where to save (the Desktop and `Falcon Debug Report.zip` by default) and writes a zip. It holds `debug-report.txt`, the open library's `metadata.json`, `mtime.json`, `tags.json` and `saved-filters.json` when they exist, and the error log as `falcon.log`. The text has sections for the app (version), the system (macOS version and build, model, CPU, logical CPUs and memory, asked of `sw_vers` and `sysctl`, with "unknown" for anything that fails), the display (window size in points and pixels per point) and the library (path, item, folder and tag counts, each JSON file's size and whether it is writable, then the other open libraries and the recent ones). Without an open library that section says so. The zip is made with `ditto` from a temporary folder that is deleted afterwards, then shown in Finder. Nothing is tested over the network or on the disk, and nothing is sent anywhere; the report may contain library paths and tag names, so look through it before sharing. A failure is logged and shown as a message.

## Dropping files from Finder

While files are dragged over the window from Finder or another app, falcon shows where they would land, as Eagle's drop areas do (`index.html` `box-container-droparea` and `sidebar-droparea`, seen): over the grid a framed hint says the files will be imported (into the open folder, when one is open); over the sidebar, that folders dropped there are imported with their subfolders; over a folder row, the row is outlined. ## Context menu search

As in Eagle (`app.bundle.js`, `showSearch: true`, seen), the item, folder, smart folder, tag, tag group, palette swatch, filter bar + and Saved menus, and the New… menu, open with a search box on top that already has focus, so you can type straight away. Typing replaces the menu with the entries whose label holds every typed word (any case), earliest match first; ↑ and ↓ move the highlight, Enter or a click runs the entry, Esc closes the menu. Disabled entries and submenu buttons are left out, as in Eagle. Entries inside submenus are searched too and listed under the submenu's name, after the top-level matches (before them when no top-level label starts with what was typed and a submenu entry's own label matches, as Eagle orders them); typing a submenu's name lists its entries. Clicking into the box doesn't close the menu. In the Saved menu the per-filter ⋯ submenus (Rename, Move, Remove) are left out of the results, so the search finds saved filters by name. The nested menus are searched as well: Change Icon in the folder and smart folder menus (while filtering, the icon grid becomes one entry per icon, labelled with its glyph and Eagle's icon name, so "film" finds the film icons), Add to Group and Move to Group in the tag menu, and the batch rename dialogs' Insert button, whose menu has its own search box and finds the Number and Date entries (a date form is listed under its source, Date ▸ Today, Modified or Created, so "modified seconds" finds one entry; `ui/menus/insert.rs`). Eagle's inspector Help button is not built: its menu is mostly online links (Help Center, Tips, Roadmap, Privacy, API documentation, Twitter, Check for Updates) beside About, Preferences and Shortcuts, which falcon has in the app menu.

The Help menu in the menu bar is registered with macOS as the application's help menu (`NSApplication.setHelpMenu`, as Eagle's `role: 'help'` does), so macOS adds its own search field at the top of it and finds every menu item of the app by title. That field is the system's, not falcon's. Eagle also has a Help button at the foot of its inspector whose menu is searchable (About, Check for Update, Preferences, Help Center, Tips, Shortcuts, Privacy, API, Twitter); falcon has no such button.

`crates/falcon-app/src/ui/menus/search.rs` wraps a menu's body without changing it: while you type, the body still runs each frame out of sight, the app collects its enabled buttons and their labels, and running an entry hands that button an accessibility click, so the menu code acts exactly as if it had been clicked. egui only builds a submenu while it is open, so the menus open theirs with `menu_search::submenu(ui, name, |ui| …)` instead of `ui.menu_button`: while the search filters, it runs the submenu's contents inline in the hidden body and reports the area they took, so their buttons are collected under the submenu's name; otherwise it is `ui.menu_button`. The item menu (Open File Location, Open With, Copy, Thumbnail Background, Export) and the folder and smart folder menus (Password, Sort Items By, Export) use it; Change Icon's icon grid is left out of the search.

## Saving

The app opens libraries in batched write mode (see [Write batching](library-format.md#write-batching)): edits made during a frame, including those from the HTTP API and background imports since the last frame, are written together at the end of the frame. Pending writes are also flushed when a library is closed and, for every open library, when the app saves its state (every 30 seconds and on quit). A failed write shows "Could not save". A `metadata.json` write is refused when the file on disk was saved by a newer Eagle or has a later `modificationTime` than falcon last saw, which means another app or a sync service changed it (see [the write guard](library-format.md#newer-libraries-and-outside-changes)). The app then shows a Library changed elsewhere alert saying falcon didn't save over it, reloads the library from disk and asks the user to redo the last change if it is missing. Other pending writes go out first. If the library can no longer be opened, because it is now from a newer Eagle or its folder is gone, it closes with a Library closed alert.

Metadata backups follow Eagle's timing (see [Backups](library-format.md#backups)). When a flush writes `mtime.json` or `metadata.json`, a backup is scheduled 1 second later, and each further write restarts the wait. Every open library is also backed up every 30 minutes. Both run `backup::backup_library` on a background thread, so the copy never blocks the window, and a library never has two running at once. The copy goes into the library's `backup/` folder, is skipped when the newest backup has the same size, and at most 100 are kept. Each new backup also replaces the library's copy in `eagle-backup/` in falcon's app data folder (`~/Library/Application Support/Falcon/eagle-backup/<fnv1a-32 of the library path>.json`), and a backup never recreates a library whose folder has gone. When a library closes or the app saves its state with a backup still waiting, it is taken right away on the main thread so a quit doesn't lose it. The timing lives in `crates/falcon-app/src/backups.rs`, whose `Schedule` takes the time as an argument and has unit tests; nothing in the tests waits on a timer.

Metadata backups have no setting: falcon backs up after a change the way Eagle does (Eagle has no preference for it either). An earlier "Back up metadata on change" checkbox that did nothing was removed; old saved state that has it still loads.

## Status messages

Short notes appear in a small rounded box at the bottom centre of the window (in the middle of the picture while the viewer is open). Only one shows at a time, and a new note replaces the old one. A note stays up while the pointer is over it.

- Quick confirmations, such as anything copied, a rating or "Refreshed", go after about a second.
- Other notes stay for three seconds, or longer when the text is long (one second less over the viewer).
- A failure ("Could not save", "Export failed" and the like) has a red mark before the text and stays for at least six seconds.
- Notes for actions that can be undone have an Undo button at the right and stay for at least five seconds. Clicking it undoes the last step, as ⌘Z does, and closes the note. It is offered after moving items to the Trash, removing items from a folder, adding or dropping items on a folder, clearing or pasting tags, and renaming, removing or merging tags. Restoring from the Trash and permanent deletes have no Undo button.
- Notes about adding or moving items to a folder end with the folder's name as a link. Clicking it opens that folder.

The import error box and the progress bars are separate and unchanged.

### Background task status

Eagle shows a small spinner beside the library name while its background queue (colour analysis of new items) has work; its tooltip reads Processing or Paused with the number left, and a click pauses or resumes the queue. falcon analyses colours as part of each import, so its queue is the import thread: while files are left, a turning ring sits beside the library name (`ui/sidebar/task_status.rs`, rules in `tasks.rs`) with the same tooltip. Clicking it pauses the queue before its next file (the file being imported finishes), shows a resume glyph and turns the strip under the toolbar to "Paused at N of M"; clicking again resumes. Thumbnail refreshes run behind their own progress window with Cancel and are not part of this queue.

## Several libraries

Falcon can keep several libraries open in one window and switch between them; Eagle can't. Each open library is a workspace with all of its own state: where you are (scope, back and forward history, search, filters, sort and layout), the selection, the viewer, its undo and redo stacks, open dialogs and its image caches. Switching keeps all of it. Global state stays shared: Preferences, shortcuts, the recent list, zoom, panel visibility, the collect window and the HTTP API server.

- **Switching:** click the library name at the top of the sidebar or press ⌘L. The menu lists the open libraries first (name over its folder, dimmed, the shown one highlighted, × to close), then recent libraries that aren't open, then Open Library…, New Library…, Show in Finder, the collect window and Preferences. ⌃⇧Tab and ⌃Tab step through the open libraries.
- **Opening** a library that is already open shows it instead of loading it twice (paths are compared after resolving symlinks). A new workspace starts with the shown library's sort and layout and is added at the end of the list.
- **The loading screen** appears while a library is read on a background thread: one chosen in the switcher, with Open Library… or dropped on the window, the libraries reopened at launch, one just created, and the missing-library screen's Try Again and Select Another Path…, so a large library doesn't freeze the window. It shows "Opening <name>" with a progress bar and a line that reads "Reading the library…" while the item folders are being listed, then "Reading items: 50 of 200", then "Almost there…". It fills the window when no library is open and is a dialog over the shown library otherwise. Only one library loads at a time; others wait their turn in a queue (`app/open_queue.rs`), and the sandbox check and backup restore run on that thread. When it finishes the library appears in a workspace of its own. At launch, the library shown before quitting (or the one given on the command line) is shown once all are read, and the command line's items, search, colour, tags page, imports and links, as well as links and files opened with falcon meanwhile, wait until then. Try Again on a folder that is still missing says so at once without a load; a path picked with Select Another Path… replaces the old one in the recent list once it has opened.
- **Storage warnings** come from a check run once on a background thread when a library opens (`crates/falcon-app/src/storage.rs`), after Eagle's warnings. It tries to open `metadata.json` for appending, creates and removes a `<ms>.tmp` folder in the library, times that round trip, and asks macOS for the volume type. A read-only `metadata.json` or a folder where nothing can be created gives a "<name> may not save changes" alert, with the reason and a hint to check permissions or move the library. A round trip slower than 1.5 s (falcon's own threshold, since Eagle's isn't in its readable source) or an NTFS volume gives a toast instead, saying the disk is slow or that NTFS drivers on macOS are slow and less reliable and that APFS or exFAT works better.
- **Outside changes** are picked up while a library is open. Each workspace polls the library's `metadata.json` and `mtime.json` every 4 seconds on its own thread (`crates/falcon-app/src/watch.rs`; see [the library format](library-format.md#newer-libraries-and-outside-changes)). A newer `metadata.json` replaces the folder tree, and the undo and redo history and any open folder edit are cleared since they no longer fit it. Items added, edited or deleted elsewhere appear, change or go, and the thumbnail cache forgets the ones that changed, and an item open in the editor that changed is closed. Falcon's own saves cause no change. This covers libraries that aren't shown as well as the one on screen.
- **A library whose folder vanishes** (moved, renamed, deleted or its drive ejected) closes without the flush and backup a normal close does, because those writes would fail or recreate files in the old place. Pending writes are discarded, and the missing-library screen opens for it.
- **The missing-library screen** is titled "Library not found" and names the path: there is no library folder there, and it may have been moved, renamed or deleted, or its drive isn't connected. It appears when opening a library whose folder doesn't exist (a recent entry marked missing, or a path passed in), when a library's folder vanishes while it is open, and at launch when the library that was shown when falcon quit is gone (a hidden library that is gone is only skipped, as before). It fills the window when no library is open and is a dialog with an extra Close button otherwise. Try Again opens the same path again and flashes "The library is still missing" if it is still gone. Select Another Path… opens a folder picker and, when a library opens from it, removes the old path from the recent list. "Can't find it? Create a new library" opens the Create a Library dialog.
- **Merge Another Library…** asks for a folder, then shows "Merge <other> into <this>?" with what would come in and Merge and Cancel buttons. The open library itself, a folder with no `metadata.json` and a library from a newer Eagle are refused with a "Can't merge that library" alert. Merge copies the missing item folders on a background thread behind a "Merging <other>" dialog that can be cancelled, then merges the folder tree. A Merge finished alert gives the numbers of items, folders and smart folders or tag groups added. If the items were copied but the folders couldn't be saved, a Merge not finished alert says so. The rules are in [Merging libraries](library-format.md#merging-libraries). The other library must be inside the sandbox.
- **Empty Cache and Reload…** asks "Empty cache and reload?" (Empty Cache and Reload or Cancel). On confirming, falcon writes what is pending, reads the shown library from disk again (restoring a backup if `metadata.json` is damaged), rebuilds its `mtime.json` from the items, drops every decoded thumbnail and preview, and flashes "Library reloaded". A large library takes a while. If the save before it fails, nothing is reloaded.
- **Import Eagle Package…** asks for an `.eaglepack` and reads it without extracting it (see [Export](library-format.md#export-eaglepack)). A dialog says how many items the package holds and how much disk space they take in this library, with Import and Cancel. When some look like items already in the library, a second dialog, titled with their count ("3 items already in the library"), asks whether to import them anyway: Import brings everything in, Leave Them Out imports the rest (Eagle's Don't Import), and closing the dialog with Esc imports everything, as dismissing Eagle's does. The import then runs behind a progress modal with a count of items and a Cancel button; Cancel stops before the next item and the items already imported stay. A file that isn't a readable package gives a "Can't import the package" alert. A package picked here goes into the open folder if one is open. Dropping an `.eaglepack` on the window does the same, and one dropped on a folder goes into that folder. Only the first package of several dropped files is taken, and the other files import as usual.
- **Import Inboard Backup…** asks for a backup folder. A folder without `InboardBackup.json` gives a "Not an Inboard backup" alert. Otherwise one top-level folder is created for each Inboard folder and the images import in the background with their names, tags, links, trashed state and dates, and a toast reports "Importing <n> images and <m> folders from Inboard", with the number of files missing from the backup. The format is in [Inboard backups](library-format.md#inboard-backups).
- **Creating** a library (New Library… in the switcher) opens the Create a Library dialog. Enter a name (not empty, none of `@ # $ % ^ & * < > : ' " / \ | ?`; at most 127 characters) and press Create or Return; Esc cancels. A system dialog then asks which folder to keep the library in, starting at the sandbox folder. A folder whose path contains "Desktop" or "Downloads" brings a warning that a library there risks being deleted by accident, with Choose Another and Save Anyway. The library is made as `<folder>/<name>.library` through the sandbox check and opened. If one already exists there the dialog stays open with a message so another folder or name can be tried. The code is in `crates/falcon-app/src/ui/dialogs/library.rs`.
- **The welcome flow** replaces the empty window on a first launch, when no library has ever been open or recent. It has three steps with Back and Next and a row of dots: a title with a one-line description, a choice of theme (shown as swatches, applied at once and saved with the preferences), and a name field with a few example names, a Create Library button and an Open Existing Library… link. Create Library checks the name as the Create dialog does and continues with the folder choice and the Desktop and Downloads warning; cancelling the folder choice stays on the step. Once any library is opened or created, the flow is marked finished in the saved state and never returns; a launch that finds saved libraries skips it. If a library failed to open at launch, the plain empty window with the error is shown instead. After the flow, and when the last library is closed, the empty window shows the title, the error if there is one, a Create Library button (opens the Create dialog) beside an Open Library button (picks an existing library folder), and a line saying a library is a folder that holds your files and their tags.
- **Closing** writes the library's pending changes, then picks the next library to the right (or the left at the end). Closing the last one leaves the empty window and stops the API.
- **Closing while tasks run:** switching to another library never stops anything, since a library in the background keeps importing and finishing its operations. Closing one does. When the library has imports in flight, a long operation behind the progress modal or an export running, the × asks "Close Library While Tasks Run": tasks are still running in <name>, closing stops them, and work already done is kept. Stop Tasks and Close tells the import to skip the files it hasn't started (they count as done, so the batch ends) and the progress modal's operation (an export included) to stop before its next item, and shows "Stopping tasks…" with no buttons. The library closes, with the usual save and backup, only once every worker has stopped, so nothing writes to it after that save. Cancel leaves everything as it was. The pending close is kept by the library's folder, since switcher positions shift (`crates/falcon-app/src/ui/dialogs/force_close.rs`).
- **Quitting while tasks run:** the same warning guards quitting, since a quit would cut off imports, a progress-modal operation or an export in any open library, the one shown or one in the background. Quit asks "Quit While Tasks Run" (tasks are still running, quitting stops them, work already done is kept) with a red Stop Tasks and Quit and a Cancel (Escape or a click outside also cancel). Stop Tasks and Quit stops the tasks of every library as above, shows "Stopping tasks…" until the workers have stopped, and then closes the window for real, so the usual save and backup on quit run. With nothing running, Quit quits at once. It asks from ⌘Q and the app menu's Quit (falcon replaces winit's Quit item, which ended the process, with one that asks the app), the menu bar icon's Quit Falcon (which also brings the window forward so the question is seen), and a window close that would quit (the Dock option off with no menu bar icon). A close that only hides the app never asks. Quitting from the Dock icon's own menu, or by logging out, is AppKit calling terminate directly, which falcon cannot intercept without replacing winit's application delegate, so it does not ask (`crates/falcon-app/src/ui/dialogs/quit_confirm.rs`).
- **Window title:** the shown library's name ("Falcon" when none is open). The title bar is hidden, so it shows in the Window menu, Mission Control and the Dock.
- **Launch:** the open libraries, and which one was shown, are saved with the app state (`libraries` and `active`) and reopened; a missing one is skipped, except that when the library that was shown is gone the missing-library screen opens for it. A library passed on the command line is opened (or shown, if it was already open) after them. State saved by older versions, which has only `library`, opens that one library.
- **API warnings:** two problems with the local API show a "Local API unavailable" alert, which stays until dismissed or until the API is restarted. When no port of the range is free (another program answers on each), it reads that the API couldn't start, names the ports, says apps and browser extensions won't reach it and points to the first port in Preferences ▸ Developer. About a second after the server starts, a background thread resolves `localhost` and tries a plain connection to each loopback address on the server's port (`crates/falcon-app/src/api_check.rs`; no HTTP request is made, and never to port 41595). If none connects, the alert says the API runs on that port but can't be reached through localhost, so browser extensions can't reach Falcon, and that a proxy or VPN may be redirecting localhost. A working start still only flashes "API on http://localhost:<port>".
- **HTTP API:** it serves the shown library and keeps its port when you switch. A `library/switch` request opens (or shows) that library in its own workspace and gives the one it replaced back its library; see [HTTP API](http-api.md#the-desktop-app).

What Eagle does (Eagle 4.0, from `js/directives/library-panel.js` and its template, `js/background.js`, `js/api-server.js` and `js/default-preferences.js`; observed unless marked):

- One library per window. The renderer keeps a single library path, and switching (`openLibrary`, then the `add-to-history-and-open` message to the background page) saves the cache, drops the current library and loads the new one in the same window. A dialog first asks to cancel running imports, downloads or saves. No code path opens a second main window for another library (inferred from the absence of one; the main-process window code isn't in the extracted renderer files).
- The library panel opens at the brand icon (`switchLibrary`) or with `library.switch`, ⌘L by default. It has a search field (fuzzy, with pinyin), then one row per entry of the `libraryHistory` setting: the library's icon (`icon.png` in the library, if any), its name without `.library`, its parent folder, and a check on the open one. Rows can be reordered by dragging, and their menu changes or removes the icon, shows the library in Finder, or removes it from the list. Below the list: Create, Load (open), Reload and Merge. ↑, ↓ and ↩ pick a row; Esc closes the panel.
- `libraryHistory` appends a newly opened library at the end, without duplicates, and keeps the user's order. A separate `pinnedLibrary` list exists.
- Item counts are not shown in the panel.
- `library/switch` over the API calls the same `openLibrary`, so the API always serves the window's library.
- Eagle has no next or previous library shortcut; `library.create` and `library.load` exist without defaults.

How falcon differs: several libraries open at once (above) and its own ⌃Tab and ⌃⇧Tab shortcuts; one window rather than one OS window per library (Eagle doesn't have several windows either); the recent list is newest first and capped at 10, with no search, pinning or reordering yet. It has icons, Merge Another Library… and Empty Cache and Reload… (Eagle's Merge and Reload).

## Layouts and display options

The toolbar's layout button opens a panel after Eagle's (`layout-panel.html`, seen), in its order: the layout; for the Grid layout, the fill mode (**Fit** shows the whole image, **Fill** crops it to fill the square); the Thumbnail option (**Speed** or **Quality**, Quality by default as in Eagle's `eagle.list.show.originalImageWhenLarge`: a jpg, png, webp, bmp or jfif card drawn larger than its 512 px grid render shows its original instead, decoded on the loader's workers at up to 1600 px into a cache of 16, about 160 MB at most, after the visible thumbnails; originals still in iCloud aren't downloaded for it. Eagle swaps once its tile height passes 600 px, which falcon's 400-point tiles never reach, so falcon asks whether the card would otherwise be enlarged); the sort, with the direction (inside a folder or smart folder, that view's own sort, as in the folder menu); the switches Show Name, Show Item Info (with what the info line shows: Dimensions, File Size, Tags, Rating, Date Modified or Date Created), Show Extension (at the end of the name), Show Extension Label (the type badge), Show Comment Count, and Show Subfolder Content; Show Sidebar and Show Inspector; and **Refresh**, which writes anything pending, reads the library again from disk, decodes the thumbnails again and reshuffles random orders. A right-click on empty grid space (in any layout, and on the empty view; not on a card, the subfolder cards or the list header) opens the same panel at the pointer, as in Eagle, and leaves the selection alone. The code is in `crates/falcon-app/src/ui/toolbar/layout_panel.rs`, the rules in `logic/`.

## Selection

Click selects one item, ⌘-click adds or removes one, ⇧-click selects the range from the last clicked item, and a click on empty space clears the selection.

Dragging over empty grid space draws a rubber band, in every layout, as Eagle's `rect-select` does (seen): every card the band touches is selected, replacing the selection; with ⌘ held when the drag starts, each touched card flips (selected ones drop out); with ⇧, touched cards join the selection (Eagle keeps the selection when a ⇧ drag starts but drops what the band leaves as it moves, so ⇧ acts nearly like a plain drag there; falcon adds, as Finder does). Shrinking the band gives back what it no longer touches. Held within 24 px of the grid's top or bottom edge (or past it), the band scrolls the grid. A drag that starts on a card still drags items. The rules are `logic::marquee_selection` and `logic::rect_hits`.

⇧→ and ⇧← extend the selection one item at a time, as Eagle's multiple select does: the selected run grows at its end away from the anchor (the item last clicked or moved to), and shrinks back toward the anchor when it already reaches past it on the other side. ⇧↓ and ⇧↑ do the same in the List layout; in the other layouts they do nothing, as in Eagle (`logic::extend_selection`).

When the selected items leave the grid (moved to the Trash, restored or deleted from the Trash, removed from the open folder, or dragged onto another folder, which moves them out), the item after them is selected, or the one before at the end of the grid, as Eagle does. Items dragged into a subfolder the view shows (with Show Subfolder Content on) stay selected.

## Hover preview

Hovering a card shows a faint zoom button in the bottom-right corner of its image (in the List layout, over the whole thumbnail). Resting on the button for 200 ms floats an enlarged copy of the image over the window, which dims behind it. Holding Z shows it at once for whichever card is under the pointer. ## Preferences

⌘, (or Preferences… in the app menu) opens a window over the main one, laid out like Eagle's: a search box above the list of panes on the left, the pane on the right, and Save, Apply and Cancel at the bottom. The panes follow Eagle's order, with separators between groups: General, Sidebar | Controls, Preview, Screenshot, Shortcuts | Notification, Password, Auto-Import | Developer. Eagle's AI, MCP and Proxy panes are not built; a pane appears only once it has a working setting. Each pane is one function in `crates/falcon-app/src/prefs.rs` that adds titled blocks to a `Page`.

Typing in the search box shows the matching blocks of every pane under the pane's name. A block matches when every word typed appears in the pane name, the block title or its keywords (case-insensitive), as Eagle's blocks carry keyword lists. The Shortcuts pane appears in the results as a button that opens it. The last pane shown is remembered across launches, as Eagle remembers it.

Edits stay in a draft until Save (also ⌘↩) or Apply; Cancel, the close button and Esc drop them, as in Eagle. A previewed theme, interface zoom or language reverts on Cancel. The values are saved with the rest of the app state.

Two Eagle settings have no counterpart in falcon. GPU acceleration is missing because falcon always draws with wgpu: eframe's `glow` backend is not compiled in, and the 3D viewer needs wgpu, so there is nothing to switch to. Color Space is missing because eframe and wgpu do not expose the window surface's colour space; falcon renders in sRGB.

What Eagle does, from `js/default-preferences.js`, `preferences.html`, `js/preferences.js` and `css/preferences.css` (all seen):

- Preferences live in one tree with groups `general`, `habits`, `shortcuts.keybinds`, `theme`, `notification`, `sidebar`, `screencapture`, `video`, `proxy`, `privacy`, `autoImport` and `developer`. Booleans are stored as the strings `'true'` and `'false'`, and choices as strings (`hoverZoom: "on"`).
- The window's sidebar (200 pt wide, 32 pt rows) has General and Sidebar, then Controls, Preview (the `habits` group), Screenshot and Shortcuts, then Notification, Password and Auto-Import, then the AI panels. A search box filters every panel by keywords.
- Save applies and closes, Apply applies and stays open, Cancel and Esc revert (including a previewed theme or zoom), ⌘↩ saves.
- The window's own size is set in Eagle's main process, which is not in the readable bundle; falcon's 720 × 500 pt is a guess (inferred).
- Built in falcon since: the menu bar icon option, the collect modal for screenshots, and screenshots with their keys, format, quality, tag, clipboard and @2x settings.
- Built in falcon since: sound effects (see below).
- Not built in falcon: vibrancy, GPU, proxy, the AI and MCP panes.

### Sound effects

What Eagle does (seen in `app.bundle.js`, `js/background.js`, `progress.html` and `js/vendors/jquery-audio.js`):

- It ships four short sounds: one for removals, one for duplicates, one for errors and a notification chime. Every sound goes through one player with a 500 ms leading-edge debounce shared by all of them: a call within 500 ms of the previous call is dropped and restarts the wait. Sounds play through the system output, so the Mac's volume and mute apply.
- The removal sound plays under `when.deleteImage` for Move to Trash, Remove from Folder and deleting a folder's contents, and under `when.deleteFolder` for deleting folders and smart folders, deleting tags, taking tags out of a tag group, deleting items for good and emptying the Trash. One action on many items plays it once.
- The screenshot sound plays when the screenshot has become an item, not when the shutter fires. A full-screen shot plays it directly; an area or window shot plays it with its "screenshot added" pop-up, so it is silent when pop-ups or their screenshot switch are off, and silent when the collect window opens instead.
- `when.extension` covers the browser extension's saves and screenshots. The duplicate dialog, the first failed import of a batch, the auto-import notice and items added through the API with a notice follow only the master switch.

How falcon does it (`crates/falcon-app/src/sounds.rs`, `app/sounds.rs`):

- The sounds are falcon's own, synthesised on first use from short envelopes; no audio files ship. Delete item is a soft filtered-noise whoosh (180 ms), delete folder two lower tones (240 ms), the screenshot a two-click shutter of bright noise (150 ms), duplicates two short blips, a failed import a low tone and the auto-import notice two rising notes. Each peaks at about a third of full scale.
- They are mixed into the viewer's rodio output stream (`Audio::play_clip`), which stays open for the session. If no sound or track has opened it yet, the first sound opens it on a worker thread and plays from there, so the window never waits; only an output device is ever opened. The viewer's volume slider doesn't affect them; the Mac's volume and mute do.
- The 500 ms debounce is Eagle's, shared by every sound; a call the switches refuse doesn't count.
- Every item and folder delete goes through the action reducer (`app/actions.rs`), which plays the matching sound once the change is saved: from the grid, the inspector, the context menus, the Edit menu, the keyboard, the viewer and the confirm dialogs alike. Move to Trash that asks first plays when it trashes; Empty Trash plays when it finishes; restoring is silent. Deleting a tag group plays nothing, as in Eagle.
- Screenshots follow Eagle's rule (`Prefs::sounds_capture`) for every capture mode, whether started from a global key, the menu bar icon or a menu. `screencapture` now always runs with `-x`, so the system shutter sound never plays over falcon's.
- The duplicate dialog opening, an import batch ending with failures and the auto-import notice play their sounds under the master switch alone. falcon has no browser extension, so nothing plays for `when.extension`, and the HTTP API's adds post no notice and play nothing.

## Themes

Eagle has seven theme choices: Auto, Light, Lightgray, Gray, Dark, Blue and Purple, in that order in `js/preferences.js` (observed). falcon offers all seven in the same order. The code is in `crates/falcon-app/src/theme.rs`:
- `Theme` is the choice.
- `Palette` holds one theme's colours.
- `p()` returns the current palette.
- `set_theme` switches it and restyles egui.
- `follow_system` runs once a frame and keeps Auto in step with macOS.

**Auto (observed in `js/preferences.js` and `app.bundle.js`).** Eagle stores Auto as `{name: "Auto", css: "auto"}` and never puts `auto` on `body`. Wherever it needs the theme, it asks Electron's `nativeTheme.shouldUseDarkColors`: true shows **gray**, false shows **light** (not dark, and not lightgray). The Preferences window listens for `nativeTheme`'s `updated` event, and the main window recomputes it when the theme changes.

falcon resolves Auto the same way, from egui's system theme (`Context::system_theme`, filled from winit's `ThemeChanged` and the event loop's appearance at start-up). When the appearance is not known yet, Auto shows gray, matching egui's dark fallback. Under Auto, falcon sets egui's theme preference to System, so the window is not pinned to an appearance and macOS changes reach egui (winit drops `ThemeChanged` while a window has its own appearance, and egui pins it for a fixed Light or Dark preference). egui's dark style gets gray's colours and its light style light's, so egui swaps its widgets by itself, and `follow_system` updates the palette `p()` returns. Neither step asks for any permission. With a fixed theme `follow_system` is one atomic load.

**Where the colours come from (observed in `style/base/_color.scss`).** `body[theme=…]` sets `--color-theme`:
- dark `#18191c`
- gray `#37383c`
- blue `#0d1630`
- purple `#1C1424`
- light `--color-white` (`#ffffff`; the map's `color-theme-light #f3f4f6` is not used by it)
- lightgray `--color-theme-lightgray` (`#e3e4e6`)

The four dark themes share one block, and light and lightgray share another (`body[theme=light], body[theme=lightgray]`, and the `light` mixin in `style/_mixins.scss` covers both). So lightgray is light's overlays, text, `#0072ef` primary and folder colours on a grey base:

## Shortcut settings

Preferences → Shortcuts lists every rebindable command by group, with its chord. The first group, Global, holds the keys that work from any app (Show falcon, Show falcon and focus the search, and the three screenshots); see Global shortcuts. A search field at the top filters the list by command name, group, id or chord (and the fixed keys by what they do). Clicking a chord starts recording: the next key press becomes the shortcut. Backspace alone clears it, Esc alone stops recording, and a letter, digit or symbol needs a modifier (function keys, Space, ↩, arrows, Home, End, Page Up/Down, Delete and brackets may stand alone). A chord another command already uses is refused with "Used by …" for 1.5 s, and the old chord stays. A changed row has a reset button, and Restore Defaults (after a confirmation) resets them all. The last group, Player, holds the video player's keys (play or pause, previous and next frame, back and forward 10 frames, volume, skip, speed and add comment). They act only while a video plays in the viewer, so, as in Eagle, they conflict only with each other: the player may use ⌘F, and its Space overrides the viewer's while a video plays. Player chords must match their modifiers exactly (⇧[ is not also [). A command can also have extra chords that work only while its binding is still the default: ⌘← and ⌥← for Back, F2 for Rename, Enter for the viewer, and * (⇧8) for expand or collapse all folders. Because Backspace alone clears a binding in the recorder, bare ⌫ can't be recorded for Back; the reset button brings it back. When a newer falcon's default lands on a chord the user had already given another command, the saved chord wins and that default is left unbound (its extra chords still work if free). The table, the parser and the recorder rules are in `crates/falcon-app/src/shortcuts.rs`.

Changes are saved as a map from command id to Eagle's accelerator text, for example `{"edit.rename.darwin": "Command + R"}`, holding only the changed commands; an empty string means unbound. Ids reuse Eagle's keybind names where Eagle has the command (`file.create.folder`, `view.zoom.in`, `find.filter.toggle`, `app.preferences`, `app.lock` (Lock falcon, ⌥⌘L), `player.prev1frame`, `player.step.forward`, …). The add-comment key N gets falcon's own id (`player.comment.add`): Eagle handles N outside its keybind table, so it can't be changed there. falcon has no thumbnail keys (`player.thumbnail.*`). When a key press matches several chords (⌘F and ⌘⇧F for ⌘⇧F), the one with the most modifiers wins. ⌘C, ⌘X and ⌘V reach egui as Copy, Cut and Paste events rather than key presses, so falcon maps them back; this also makes ⌘C in the grid work, which the old hard-coded check missed.

What Eagle does, from `js/default-preferences.js`, `js/preferences.js`, `js/services/shortcut-manager.js` and `js/directives/shortcut-input.js` (all seen):

- `shortcuts.keybinds` maps 150 names (`file.create.folder`, `view.zoom.in`, …) to Electron accelerators such as `CmdOrCtrl + Shift + N`. On load, `CmdOrCtrl` is rewritten to `Command` (macOS) or `Ctrl`. Platform pairs such as `edit.rename.darwin` (⌘R) and `edit.rename.win32` (F2) show only on their platform.
- The recorder writes modifiers in the order Ctrl, Command, Shift, Alt, then the key; letters and digits need a modifier; Backspace alone clears.
- Conflicts are checked within a group's `conflict` scope: player keys only clash with other player keys, everything else with everything else. A clashing chord is refused, the old one stays, and a note names the other command for 1.5 s.
- Restore Defaults asks first, then reloads the defaults (plugin shortcuts too). The window has a shortcut search box; falcon has one too.
- Every falcon command that has an Eagle counterpart is listed under Eagle's id, with Eagle's macOS default (empty is unbound): the macOS-only ids carry their `.darwin` suffix (`edit.rename.darwin`, `edit.remove.trash.darwin`, `edit.remove.folder.darwin`, `view.reveal.darwin`, `view.duplicate.darwin`). Overrides saved by earlier versions under `edit.rename`, `edit.remove.trash` and `edit.remove.folder` are moved to the new ids when the app state loads (an override already saved under the new id wins). The defaults differ from Eagle's table in two places on purpose: the rating rows (`organize.rating.*`) default to the bare digits 0–5 that Eagle hard-codes, and the layout rows follow Eagle's keys rather than its swapped names. Eagle ids with no falcon action have no row: the link, Pinterest and ArtStation importers, Open Library (`library.load`), reverse image search, Merge Images, the import-date, semantic, image and other filters, Open With and Add to Folder (`organize.folder.add`). Commands without an Eagle key stay menu-only: Undo, Redo, Cut, Import Files, Find Duplicates, Zoom, Documentation, About, Error Logs and Debug Report.
- falcon uses ⌘R for rename, Eagle's macOS default, and keeps F2 as an extra chord. It keeps its own ids for commands Eagle lacks or names differently (`view.viewer`, `go.back`, `edit.select.all`, `edit.folder.arrange.*`) (inferred mapping). Eagle's `view.layout.grid` and `view.layout.waterfall` are attached to Waterfall and Grid respectively, while falcon's ids of the same names mean its Grid and Waterfall layouts; only the defaults follow Eagle (⌥1 Waterfall, ⌥3 Grid).

## Collect window

⌘⇧K, or Show Collect Window in the library menu, opens a small (300 × 600 pt) borderless window that floats above all other apps. Files dropped on it, or pasted into it with ⌘V (copied files or image data), go through the normal background import into the folders picked in its list.

- **Folders:** a click picks just that folder; ⌘-click adds a folder to the pick or takes it out. Picked rows show a check mark. With nothing picked, items go to the library root ("No folder" clears the pick). The pick is saved with the preferences, and picked folders missing from the open library are ignored. A search box narrows the list by any part of a folder's path.
- **Recent:** after each collect the destination folders move to the front of a list of the last 20. When there are recent or picked folders, and the library has more folders than that, the list opens with a Recent block (picked folders first, then up to five recent ones, each shown with its full path), a line, and then every folder in tree order. While searching, the Recent block is filtered too, and folders in it are left out of the list below. Right-click a row in the block and choose Remove from Recent to drop it.
- **New folder:** when the search text is not empty and no folder is named exactly that, the last row reads New Folder "text". Clicking it, or pressing Enter when it is the only row, makes a top-level folder with that name, picks it and clears the search. Creating it this way is not an undo step.
- **Name, description and tags:** the fields above the list apply to what is collected next. Name is used only when exactly one file is collected (the file's extension stays). Description becomes the item's annotation. In the tag field, Enter or a comma adds a tag; each tag chip has a × to remove it; while typing, up to eight suggestions from the library appear (starred tags first, then recently used, then the rest) and a click adds one. Pasting uses the same fields. The three fields are cleared after each collect; the folder pick stays.

Drag the header to move it; ×, Esc or ⌘⇧K close it (Esc first leaves a field being typed in). Its position is remembered between launches. The code is in `crates/falcon-app/src/collect.rs`; the name goes through `ImportOptions::name`.

It is a second OS window (an egui immediate viewport with `with_always_on_top` and `with_decorations(false)`). In eframe 0.37 each viewport has its own winit window and input, and `WindowEvent::DroppedFile` lands in that viewport's `raw.dropped_files`, so drops work on it directly; no fallback was needed. On a backend without multiple viewports egui draws it as a panel inside the main window instead, and drops there go to the main window's import.

What Eagle's collect window is, from `collect-window/` and `js/background.js` (seen):

- It is not a drop target. It opens for one incoming item, when the browser extension adds an image (`general.showCollectModal`, "ask me where to save", off by default, also switchable through the API) or after a screenshot (`general.showCaptureCollectModal`).
- Left side (240 pt): the image preview with its dimensions, a 1–5 rating, an editable title and description, and tags. Right side: a searchable folder list with recent folders first, multi-select and creating a folder; choosing a folder saves the item there with the folder's auto-tags and closes the window.
- The window is frameless with 8 pt rounded corners on a translucent background. Its size, position and always-on-top setting are set in Eagle's main process, which is not in the readable bundle (inferred: small, centred, on top).

falcon keeps the folder chooser and the always-on-top window and also works as a drop target. It has no browser extension, so its one incoming item is a screenshot, as in Eagle's `showCaptureCollectModal` case. Not built: the rating, a preview of the item, and dropping images straight from a browser (macOS hands winit only file drops, so browser image drags that carry no file are ignored).

With Preferences ▸ Screenshot ▸ "Choose where each screenshot is saved" on, an area or window screenshot does not import at once. The window opens (and comes to the front) with the drop zone replaced by a Screenshot block that names the file and has Save and Discard buttons. Name holds "Screenshot - date time" and Tags holds "Screenshot" (unless tagging is off); both can be edited. Save adds the screenshot to the folders picked in the list, or the library root with none, with the name and tags as they stand, then moves those folders to the front of Recent, as a collect does. Discard drops it, and closing the window drops everything waiting. More screenshots taken meanwhile queue behind the first, and the block reads "Screenshot (and N more)"; each Save or Discard brings the next one's name and tags into the fields. While one waits, drops and pastes are refused with "Save or discard the screenshot first". Save is off when no library is open. A screen screenshot never waits here, as in Eagle. The waiting state is `collect::Pending`; the file stays in falcon's temp folder until the import copies it in or Discard deletes it.

## Screen capture

Eagle captures to the library from a global key or its tray icon. falcon does the same on macOS through the system's `screencapture`, with the three modes of Eagle.

What Eagle does (seen in its shipped source, the keys and defaults under Preferences):

- On macOS an area is captured with `screencapture -x -i -o -t png` and a window with `-x -w -o -t png`, into a temporary PNG. The full screen is taken from the display under the pointer through Electron's desktop capturer.
- The picture is converted to the chosen format and quality. When @2x is off on a scale-2 screen the picture is halved. The item is named "Screenshot - YYYY-MM-DD HH.mm.ss", gets the tag "Screenshot" when it has no tags and auto-tagging is on, and is copied to the clipboard when that is on.
- A capture request is ignored while one is running, and it needs an open library.
- An area or window screenshot opens the collect window when `showCaptureCollectModal` is on. Otherwise Eagle shows its own pop-up (when the notification master switch and the screenshot switch are on) and imports. A full-screen screenshot never opens the collect window and shows no pop-up; it plays a sound when sound effects are on. The sound of an area or window screenshot comes with its pop-up.

How falcon does it (`crates/falcon-app/src/capture.rs`, `app/system.rs`):

- A capture is started by a global key, a menu bar icon item or the same command from elsewhere. With no library open it says "Open a library to take screenshots into". A request while one is running is ignored. A locked falcon takes no screenshots.
- The pointer's screen decides the scale (`backingScaleFactor`) and the screen number used by the full-screen mode. Area and window run `/usr/sbin/screencapture` with Eagle's arguments; the full screen runs `screencapture -x -D n -t png`, silent like the others, since falcon plays its own capture sound (see Sound effects in the preferences section). A cancelled pick (Esc) leaves no file, and falcon then does nothing.
- The PNG is written into `falcon-paste` in the system temp folder, the same folder pasted images use. It is converted with `falcon_library::export::convert_bytes` to the chosen format and quality (a PNG at full size is only renamed), halved on its longer side when "Keep full Retina resolution (@2x)" is off and the screen has a scale of 1.5 or more, and named "Screenshot - YYYY-MM-DD HH.mm.ss". Two shots in one second get " 2", " 3" and so on in the file name.
- With "Copy screenshots to the clipboard too" on, the worker thread puts the picture on the clipboard as image data; a failure goes to the error log.
- The screenshot then goes into the library root with the tag "Screenshot" (unless tagging is off) as an ordinary background import, with no folders; see Screenshots in the import chapter. With "Choose where each screenshot is saved" on it waits in the collect window instead, for an area or window shot only.
- A failure shows "The screenshot failed: …" as an error note and is written to the error log.
- The "Screenshot added" notification is posted for an area or window screenshot that goes straight in, when its switches are on. A batch that held only screenshots, imported straight in or saved from the collect window, does not also post "Import finished".

- The capture sound plays as the screenshot goes into the library, under the rules in Sound effects.

Not built: Eagle's plugin and extension capture paths.

## Menu bar icon

Eagle shows a tray icon on macOS (`general.showMenuItem`, on by default) with Show Eagle, Capture Area, Capture Window, Capture Full Screen and Quit Eagle. falcon shows a menu bar icon the same way while Preferences ▸ General ▸ "Show the falcon icon in the menu bar" is on, which it is by default. Turning it off removes the icon at once.

- The icon is the SF Symbol "bird" as a template image, which follows the menu bar's light or dark colours. If the symbol is unavailable the button shows the title "Falcon".
- The menu holds Show Falcon, a separator, Screenshot of an Area, Screenshot of a Window, Screenshot of the Screen, a separator and Quit Falcon. Each of the first four shows its global key beside it; a capture item shows no key while the screenshot keys are off, and a command with no key shows none.
- Show Falcon brings the main window to the front, restoring it if it is minimized or hidden. The screenshot items start a capture. Quit Falcon quits as the app menu's Quit does.
- The menu is rebuilt only when the keys it shows change. Locked, only Show Falcon acts.
- The code is `crates/falcon-app/src/tray.rs`; the choices are queued and acted on in the next frame, as the menu bar's are.

## Global shortcuts

Eagle has five global keys (`global.show.eagle`, `global.show.search`, `global.capture.area`, `global.capture.window`, `global.capture.full`; only the area key has a default, `CmdOrCtrl + Alt + E`). falcon has the same five as the Global group at the top of Preferences ▸ Shortcuts, with the same defaults: Show falcon, Show falcon and focus the search, Screenshot of an area (⌘⌥E), Screenshot of a window and Screenshot of the screen. The three capture rows are shown again in Preferences ▸ Screenshot.

- They work from any app. falcon registers them with Carbon's `RegisterEventHotKey`, which is still the only system API for app-wide hot keys and needs no accessibility permission. They are not read from egui's input, so they never fire window commands.
- The capture keys are registered only while "Use the screenshot keys" is on (`screencapture.shortcutsEnable`). It is off by default, where Eagle has it on: Eagle is often running too and holds ⌥⌘E. The area key still defaults to ⌥⌘E, so turning the switch on gives Eagle's layout. Show falcon and Show falcon and focus the search are registered only once bound; neither has a default.
- Show falcon brings the window to the front. Show falcon and focus the search also closes the viewer and puts the cursor in the search box, when a library is open. While falcon is locked only the Show keys act, and they show the lock screen.
- While Preferences is open the global keys follow the settings being edited, before Save: turning "Use the screenshot keys" on or off, or recording a new chord, registers the keys again at once, and Cancel brings back the saved ones. While a row waits for a key press all global keys are let go, so the recorder can take chords the system would otherwise swallow.
- A chord another app already holds is refused by the system, and the other chords still work. The key's row, in the Screenshot pane and in the Shortcuts pane's Global group, then says so in orange, for example "⌥⌘E is taken by another app", until the switch or the chord changes and registering succeeds (falcon tries again on each change). Outside Preferences (at launch, or after Save) an error note says the same, for example "⌘⌥E can't be used for “Screenshot of an area”: another app has it". Only keys with a key code on the system's ANSI layout can be registered; a chord without one is left out.
- The recorder's conflict check counts the Global group with the ordinary commands, as in Eagle: a global chord cannot repeat another command's chord. The in-app key handler skips the Global group, so a global chord never fires a window command.
- The code is `crates/falcon-app/src/hotkeys.rs` (registration and key codes) and `app/system.rs` (acting on presses).

## System notifications

Eagle's pop-ups ("Import Successful", "Export Successful", the screenshot pop-up) are its own windows, not system notifications. falcon posts macOS notifications instead (`crates/falcon-app/src/notify.rs`).

| Title | Text | When |
|---|---|---|
| Screenshot added | The item's name | An area or window screenshot went straight into the library; "Show a notification for each screenshot" |
| Import finished | "N items added to the library" | A background import added items; "Say how many items an import added". Not posted for a batch that held only screenshots (also those saved from the collect window) |
| Export finished | The in-window note, for example "Exported 3 items" | An export finished; "Show a notification when an export finishes" |

- Each follows its switch in Preferences ▸ Notification under the master switch "Show notices". All are on by default.
- They use the UserNotifications framework through `msg_send`, because the framework crate in the local cache binds an older objc2 than the app. The framework needs a bundle identifier, so they work only in the bundled app made by `scripts/bundle.sh`. Run unbundled (for example `cargo run`) they are dropped without a message.
- The first one asks macOS for permission (alert and sound). Later ones use the answer given.
- macOS shows them only while falcon is not the active app, so they never double the notes shown in the window.
- Clicking one only brings falcon forward. It does not select or preview the item, as Eagle's pop-up does not either.

## Rotate, flip and crop

The viewer bar has Rotate Left and Rotate Right and a Flip button for jpg, png, webp and bmp, and Crop for jpg, png and webp. Flip mirrors horizontally, or vertically with ⇧ held while clicking, and ⇧F (rebindable) flips horizontally, as Eagle's single flip button and `edit.image.flip` shortcut (`Shift + F`) do (seen in `preview-window.js` and `default-preferences.js`). Eagle's button also mirrors a playing video; falcon's appears for images only. The card menu offers Flip Horizontal and Flip Vertical as two entries, for every selected item in those formats. By default all of these rewrite the original (see [Crop and rotate](thumbnails.md#crop-and-rotate-observed)). The crop tool starts on the whole image. Drag its edges or corners, or drag inside it to move it; while you drag, `x:… y:…, W:… H:…` in pixels shows underneath. The bar has width and height fields showing the rectangle's size; type a number and press Enter (or leave the field) to resize it from its top-left corner, kept inside the image (Enter in the width field moves to the height field, Esc reverts, and while a field has focus the crop keys don't act). Save asks for confirmation, then overwrites the original. Save As crops into a new item instead (`Library::crop_item_as_new`), leaves the original alone, needs no confirmation, closes the viewer and selects the new item. ⇧C opens the tool and, while it is open, saves. These edits can't be undone, so they clear the undo history.

Preferences ▸ Preview ▸ Image has Eagle's "Rotate and flip images" choice (`imageRotateMode`): **Writes to the file** (the default) or **Changes the preview only**. In preview-only mode the viewer's rotate and flip buttons, ⇧R, ⇧F and the Edit ▸ Edit Image commands, and the item menu opened by right-clicking the picture, act on the image shown in the viewer by turning and mirroring how it is drawn (fit-to-window uses the turned size) and write nothing. The turn is dropped when the viewer moves to another item or closes, and when the crop tool opens (its rectangle is in file pixels). Region comments are hidden while the picture is turned. The card menu in the grid, and items other than the one in the viewer, always write to the file. The turn and mirror math (`ViewTransform`) is in `ui/viewer/crop.rs`. The rectangle math is in `ui/viewer/crop.rs`.

## iCloud Drive

Libraries kept in iCloud Drive with Optimise Mac Storage on have most originals and thumbnails evicted: `ls -lO` shows the flags `compressed,dataless` (seen on a real library), `stat` still reports the full size, and the first read blocks until iCloud has downloaded the file. `icloud.rs` tells these apart from `stat` alone: the `SF_DATALESS` bit (`0x40000000`) of `st_flags`, or a missing file with iCloud's older `.NAME.icloud` placeholder beside it.

Opening such an item in the viewer shows "Downloading from iCloud…" over the dimmed preview, with a moving bar, while a background thread asks iCloud for the file (`NSFileManager startDownloadingUbiquitousItemAtURL:error:`) and checks every 250 ms until the flag clears; then the item opens as usual (image, GIF, audio, video, font or PDF). An error from `NSURLUbiquitousItemDownloadingErrorKey`, or no answer within 20 minutes, shows the reason and a Try Again button. Files the ubiquity API refuses (another file provider) get a background read of their first byte instead. Moving to another item or closing the viewer stops the polling but never cancels or evicts anything at the system level. Progress is not shown as a percentage: NSURL has no progress key, and `NSMetadataQuery`'s would need a query per file (inferred to be not worth it). Local files take the same path as before with one extra `stat`.

Where originals are read:

| Where | Thread | With a dataless file |
|---|---|---|
| Grid, preview and full-size decodes, QuickLook renders (`loader.rs`) | Loader workers | A worker waits for the download; the UI does not |
| Viewer: GIF, WebP and APNG frames, `Video::open`, audio decoding, font specimen, PDF | UI | Held behind the download screen until local |
| Animated grid cards and hover previews | UI | Not played: the card keeps its thumbnail (one `stat` when playback would start) |
| Waveforms, duplicate scan, background imports | Background threads | Wait in their own thread |
| HTTP API | Server thread | `/api/item/thumbnail` returns a path and reads nothing. The add-from-path routes import while holding the library lock, so adding a dataless file through the API still holds the window until it has downloaded (not yet handled) |

## Folder covers

Eagle shows covers only on the subfolder cards at the top of a folder's content (`sub-folder-list` in `index.html`), not in the sidebar. From `calculateImageBinding` and `setFolderCover` (observed):

## Export and copy-out

Export to Computer (⌘E, or Export ▸ Export to Computer… in the item menu) copies the selected items' originals into a folder chosen in a dialog. Each file keeps its name, `<name>.<ext>`, and its modification time. Names that clash within the export, ignoring case, are numbered as Eagle numbers them: two `pic.png` become `pic-1.png` and `pic-2.png`, padded to the widest number (`pic-01.png` … `pic-10.png`).

When files of the same names are already in the folder, falcon asks first, saying how many. **Replace** overwrites them. **Keep Both** leaves them and numbers the new copies, with the file already there counting as the first (`pic.png` exists, so the copy is `pic-2.png`). Eagle's prompt offers only Overwrite or Cancel, and its item export then numbers the copies anyway; its folder export overwrites.

The copy runs on a background thread behind the shared progress modal ("Export to Computer", "3 of 10", the file being written, and Cancel), as Eagle shows its export progress. Cancel stops it before the next file and keeps the files already written, saying "Stopped after exporting 3 of 10 items"; one export or other long operation runs at a time. Each file is written under a temporary name beside its destination and renamed into place, so a failed copy never leaves half a file. When it ends, falcon says "Exported N items" (with any failures) and, as Eagle does, shows the files in Finder, or the folder when there are more than 500.

A folder, a subfolder or a smart folder exports the same way from its menu (Export ▸ Export to Computer…) or from the inspector's Export button while it is open. A folder becomes a directory tree under the chosen folder: one directory per folder and subfolder, holding the originals of the items filed directly in it, so an item in two folders is copied into both. Directory names are cleaned up as Eagle does on the Mac (tabs and runs of spaces become one space, `:`, `/` and `\` become spaces, a trailing dot goes, and an empty name becomes "Untitled"). Two sibling folders whose names clean up alike share a directory, with clashing files numbered. Items in a locked folder that hasn't been unlocked are left out, and the menu entry is disabled on a locked folder, as in Eagle. A smart folder becomes one flat directory of its items, without its subfolders, as in Eagle. When the folder's directory already exists, falcon asks the same Replace / Keep Both question; both export into the existing directory. When the copy ends, Finder shows the new directory.

Export as .eaglepack (⇧⌘E, or the Export submenu of the item, folder and smart folder menus and of the inspector's Export button) asks where to save, suggesting `Untitled.eaglepack` for items and `<folder name>.eaglepack` for a folder, then writes the pack on a background thread behind a progress modal ("3 of 10", with Cancel) and shows it in Finder. Cancel removes the unfinished file, so nothing is left at the chosen path. Items are packed with their folders cleared, a folder with its subfolders, and a smart folder as one plain folder of its items; an empty smart folder exports nothing, as in Eagle. The format is described in [Export (`.eaglepack`)](library-format.md#export-eaglepack).

Export in Format (⇧E, or the item menu's Export ▸ Export in Format…) converts the selected images. A dialog picks the format (JPG, PNG or WebP), the quality for JPG and WebP (1 to 100, default 90; WebP at 100 is lossless) and the longest side: the original size, 4096, 2048, 1920, 1280, 1024 or 512 px, or a custom number. Images are only scaled down (Lanczos), never up; JPG puts transparent parts on white. Then a folder is chosen, and the files are named `<name>.<new extension>`, with the same clash numbering and Replace / Keep Both prompt as Export to Computer. Raster images falcon decodes (PNG, JPEG, WebP, GIF's first frame, BMP, TIFF, ICO) and SVG (drawn at its natural size) can be converted; other items are skipped, and the dialog says how many. The conversion runs on the background thread behind the same progress modal (titled Export in Format), with Cancel. Eagle's own dialog for this comes from its separate Custom Export plugin, which is not in the app's source, so falcon's options are its own.

Export to CSV (the item menu's Export submenu, the inspector's Export button for the items shown in the open folder or smart folder, or a key that is unbound by default, as in Eagle, which then takes the selection or else every item shown) saves one row of metadata per item. The columns follow Eagle's order: id, name, extension, width, height, duration, source URL, notes, comments (one per line), tags and folder names (each joined with ", "), size in bytes, rating, import and modification times as `YYYY-MM-DD HH:MM:SS` in UTC, and the original's path. Zero or missing numbers are left empty, as in Eagle. The header text is falcon's own. A field is quoted, with quotes doubled, only when it holds a comma, a quote or a line break; lines end in `\n` and the file is UTF-8 with a byte order mark, as Eagle writes it. Finder then shows the file. The writer is `export::csv` in the library, a few lines with no CSV crate.

The item menu's Copy, Copy File Path and Copy submenu entries (also in the image viewer's right-click menu, which is the item menu) put files, text or images on the clipboard, for every selected item as Eagle does:

| Entry | Key | What is copied |
|---|---|---|
| Copy | ⌘C | The originals, as files (`App::copy_items`). One jpg, jpeg, png or bmp also goes as its pixels, as Eagle does: `clip_image::copy` puts the image data (`public.png` or `public.jpeg`, plus `public.tiff`; a bmp as TIFF only), the original's `public.file-url` and `NSFilenamesPboardType` on the general pasteboard at once, so an image editor pastes pixels and Finder pastes the file. Several items, other formats and originals still in iCloud (copying the pixels reads the file) go as files only, and so does a single picture when the pasteboard refuses it |
| Copy File Path | ⌥⌘C | Each original's path, one per line |
| Copy ▸ Link | unbound | Each item's local API link, `http://localhost:<port>/item?id=<id>`, one per line, as Eagle's Copy Link writes it with its own port. The port is the running API's, else the first one set in Preferences; the API answers the link with a redirect to the item's `eagle://` link |
| Copy ▸ Eagle Link | unbound | Each item's `eagle://item/<id>` link, one per line, which opens the item in falcon (see [HTTP API](http-api.md#eagle-links)) |
| Copy ▸ Source URL | unbound | Each item's source URL, one per line (falcon's own entry); items without one are skipped, and a message says when none has one |
| Copy ▸ Folder Path | ⌥⇧⌘C | Each item's `<id>.info` folder with a trailing slash, one per line, as Eagle copies it |
| Copy ▸ Thumbnail | unbound | One item: its thumbnail as an image (the original for an image with no thumbnail). Several: their thumbnail files as files, as Eagle copies them |
| Copy ▸ Base64 | unbound | One item only (disabled for several, as in Eagle): a `data:image/…;base64,` URL of the original for JPEG, PNG, WebP and GIF, otherwise of the thumbnail, whose real format (usually WebP) names the type. Eagle labels every thumbnail `webp` |
| Copy ▸ Name | unbound | Each item's name, one per line |

Base64 and a single thumbnail read the file on the window's thread, so an item still in iCloud is refused with a message instead of holding the window. The unbound copies can be given keys under Preferences → Shortcuts (Eagle's `edit.copy.*` ids, `edit.copy.eaglelink` for Eagle Link; Link and Source URL have falcon's own, `edit.copy.link` and `edit.copy.sourceurl`).

Where files go and how they are named is worked out in `falcon_library::export` (a `Plan`, with tests); `ui/dialogs/export.rs` asks, runs and reports. Exports write only inside the folder picked in the dialog.

## Running it

```sh
cargo run -p falcon-app -- path/to/Some.library [ITEM…|FILE…]
scripts/bundle.sh   # builds target/release/Falcon.app
```

One item id (or an `eagle://item/<id>` link) opens that item in the viewer. Several ids select them. Files are imported.
