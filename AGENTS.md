# Notes for coding agents

- The workspace is `crates/falcon-library` (library format, import, search), `crates/falcon-server` (HTTP API), `crates/falcon-video` (AVFoundation playback with an FFmpeg fallback; its `tests/avfoundation.rs` runs without the test harness so the player is on the main thread), `crates/falcon-ffmpeg` (the fallback: an LGPL FFmpeg opened at run time, built by `scripts/build-ffmpeg.sh` into `target/ffmpeg`; its decoding tests run only when that exists), `crates/falcon-ifc` (the web-ifc IFC geometry engine, compiled from the sources `scripts/fetch-web-ifc.sh` puts in `target/web-ifc` into `falcon-ifc-worker`, a separate executable each read runs in; without them no worker is built and IFC falls back to the tessellated reader), `crates/falcon-pdf` (PDFKit pages, text and search; a `Document` stays on the thread that opened it), `crates/falcon-ai` (AI Models: the providers, keys in the Keychain and the one interface AI features call; its `tests/ollama.rs` is ignored unless run by hand), `crates/falcon-clip` (AI Search: the CLIP model through candle, its download, the index and the worker; only the app depends on it, so nothing else rebuilds the ML crates; its `tests/real_model.rs` is `#[ignore]`d and needs the model's files), `crates/falcon-app` (egui desktop app) and the `falcon` CLI in `src/`.
- Run `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings` before committing. Both must pass, and CI runs them on macOS, Linux and Windows. From Linux, `scripts/check-macos.sh` type-checks the macOS build.
- macOS is the primary platform and Linux and Windows are kept working from the same branch. Keep OS differences inside platform modules (`mac.rs`/`other.rs`, `mod platform`) behind one function, not in feature code. A feature can land on macOS first if other systems have a clean "not available" path. `cargo clippy` off macOS allows dead code, since some is only called on macOS; macOS keeps the full check.
- `scripts/package-macos.sh` builds the macOS .dmg (Apple Silicon, signed ad hoc, not notarised) , `scripts/package-linux.sh` the Linux AppImage and .deb and `scripts/package-windows.sh` the Windows installer (per-user, from `scripts/falcon.nsi`, not signed, run in an MSYS2 UCRT64 shell); all need `scripts/build-ffmpeg.sh` first. Pushing a tag `vX.Y.Z` matching `Cargo.toml` publishes all four as one GitHub release, which the website's download links follow; a pull request that changes the packaging builds them without publishing. Update `docs/release-notes.md` first.
- Library writes must stay byte-compatible with existing libraries. `crates/falcon-library/tests/fixture.rs` checks round trips against a library in `fixtures/`, which is gitignored and supplied locally; without it, those tests skip.
- The app draws everything with egui painters. Colours and sizes live in `crates/falcon-app/src/theme.rs`, and UI-independent logic lives in `crates/falcon-app/src/logic/` (one file per domain, re-exported as `crate::logic::*`), which has unit tests.
- `docs/` is an mdBook describing each part. When you change behaviour, update the matching chapter.
- The app and CLI only open libraries inside `~/Falcon Sandbox` (or `$FALCON_SANDBOX`); see `crates/falcon-library/src/sandbox.rs`. Never weaken this or point it at real libraries. Copy a library into the sandbox to test with it.
- On Windows the home folder is `USERPROFILE` (`sandbox::home_dir`), never `HOME`, which only Git Bash sets; run the tests with `HOME` unset as well as set. An item's name stays as it came in the metadata, and `disk_name::on_disk` is what it is called on disk, so build an item's file names through `Item::original_path` and `Item::thumbnail_name`.

## falcon-app layout

Each feature owns its state struct and its module; `App` holds `feature: FeatureState`. A new feature adds files (a state struct plus an `impl App` block in its own module); it does not grow `app/mod.rs`, `app/state.rs` or `logic/mod.rs`. Put pure, testable rules in a crate-root module or `logic/`, drawing in `ui/`.

Under `crates/falcon-app/src/`:

- `app/` is the core. `mod.rs` holds the `App` struct, `App::new`, `impl eframe::App` and `draw` (the frame layout: sidebar | central | inspector, viewer or toolbar + filter bar + grid, dialogs, toasts). `state.rs` holds `Workspace` (one per open library), `ViewState`, the edit buffers and drag payloads, and `Saved` with `save_state`. `actions.rs` holds `Action` and the reducer that applies it under the library lock (`apply_actions`, undo labels, bulk confirm). `commands/` holds `run_command`, `keyboard` and the menu bar glue (`find.rs`, `items.rs`). `library.rs` opens, focuses and closes libraries and runs the server, preferences and lock. `navigation.rs` holds `go`, back/forward, layouts per view and clicks. `import.rs` holds drops, imports and paste. `image_edit.rs` holds the image edit actions.
- `ui/` draws, as `impl App` blocks: `widgets.rs` (galley, icon, icon_button, field, chip, prop, wide_button, paint_thumb_bg…), `sidebar/` (with `folders.rs`), `organize.rs` (folder icons, sorts, passwords, tree drags, tag groups, saved filters), `toolbar/` (with `layout_panel.rs`), `filter_bar/` (with `media.rs`), `grid/` (cards, list rows, marquee, `tags_page.rs`, `empty.rs`, `duplicates.rs`, `covers.rs`, `drag_out.rs`), `drop_hint.rs`, `inspector/` (with `tag_picker.rs`), `viewer/` (shell in `mod.rs`; `image.rs`, `gif.rs`, `video.rs`, `audio.rs`, `font.rs`, `pdf.rs`, `text.rs`, `preview_window/`, `crop.rs`, `comments.rs`, `modes.rs`, `open.rs`), `dialogs/` (one file per dialog: `confirm.rs`, `smart.rs`, `export.rs`, `library.rs`, `library_notices.rs`, `quick_switch.rs`, …), `menus/` (item and tag menus, `search.rs` for type-to-filter menus) and `toast.rs`.
- The crate root holds feature modules that never `impl App`: models, rules with tests and platform glue (`anim`, `audio`, `auto_import`, `backups`, `loader`, `menu` (AppKit menu bar), `prefs`, `shortcuts`, `tags`, `theme`, `toast`, `watch`, `workspaces`, …). `prefs.rs` and `collect.rs` draw their own windows from their own state.
- `logic/` is split by domain: `scope`, `format`, `layout`, `filters`, `audio`, `duplicates`, `libraries`, `folders`, `selection`, `drops`, `viewer`, `image_viewer`, `display`.
